================================================================
 KY安全管理（現場KYアシスト） API認証方法・データ保存先まとめ
================================================================
※ 本書には実際のAPIキーは記載していません。キーは管理者が別途保管してください。

----------------------------------------------------------------
1. 全体像
----------------------------------------------------------------
・各PCにインストールしたEXE（KY安全管理.exe）が、写真とKY入力内容を
  Google Cloud Vertex AI（Gemini Flash）へ送って解析します。
・解析結果（履歴・写真・PDF等）は、各PCではなく共有の「データ保存先」
  （NAS / Googleドライブ(I:) / ローカルフォルダ）に保存されます。
・AI接続先は Vertex AI の1種類に固定されています（画面での切替不可）。

  [各PC] --(HTTPS + APIキー)--> [Vertex AI / Gemini]
     |
     +--(ファイル保存)--------> [共有データ保存先 data_root]

----------------------------------------------------------------
2. API認証方法
----------------------------------------------------------------
2-1. 認証方式
  ・Vertex AI の APIキー方式です（サービスアカウントJSONやOAuthは使いません）。
  ・リクエスト送信時、HTTPヘッダー「x-goog-api-key」にAPIキーを付与します。
  ・呼び出し先:
      https://{リージョン}-aiplatform.googleapis.com/v1/projects/{プロジェクトID}
        /locations/{リージョン}/publishers/google/models/{モデル名}:generateContent
    （リージョンが global の場合のみ、ホストは aiplatform.googleapis.com）

2-2. 認証情報の置き場所：各PCの secrets.env
  ・EXEと同じフォルダに置く「secrets.env」で管理します。
  ・設定項目:
      VERTEX_API_KEY         … 必須。未設定だとアプリは起動時にエラー終了します
      GEMINI_MODEL           … 利用モデル（未設定時の既定: gemini-2.5-flash）
      GOOGLE_CLOUD_PROJECT   … Google CloudのプロジェクトID（配布物作成時に必須）
      GOOGLE_CLOUD_LOCATION  … リージョン（未設定時の既定: us-central1）
  ・開発時（config.jsonなし）は、プロジェクト直下の .env を読み込みます。

2-3. 取り扱いルール
  ・secrets.env は NAS / 共有フォルダには置かないでください。
  ・メール・画面共有・公開リポジトリ（Git）に載せないでください。
  ・会社指定の管理者用保管場所で別管理してください。
  ・アプリ側でも、画面表示・保存テキスト・ログにAPIキーが混入しないよう
    「[非表示]」に置換する処理を入れています（キー自体は記録しません）。
  ・config.json にはAPIキーを書きません（保存先・現場情報のみ）。
  ・キー漏えいが疑われる場合は、Google Cloud側でキーを再発行（無効化）し、
    各PCの secrets.env を差し替えてください。

----------------------------------------------------------------
3. 設定ファイルの役割（各PCのEXEと同じフォルダ）
----------------------------------------------------------------
  ファイル        内容
  --------------  ------------------------------------------------
  KY安全管理.exe  アプリ本体
  config.json     project_id（現場ID）・project_name（現場名）・
                  data_root（データ保存先の絶対パス）・storage_type
                  （local または nas。省略可、パスから自動判定）
  secrets.env     APIキー等の認証情報（上記2-2）
  README.txt      配布時の案内

  config.json の記載例（バックスラッシュは2個ずつ書く）:
    {
      "project_id": "001",
      "project_name": "芝原改良工事",
      "data_root": "I:\\マイドライブ\\KY安全管理\\001_芝原改良工事\\data"
    }

  ・data_root が空、または config.json が無い状態で起動すると、
    「初期設定」画面が表示され、保存先をフォルダ選択またはパス入力で
    指定できます（接続確認あり）。APIキーはこの画面では設定しません。

----------------------------------------------------------------
4. データの想定保存先
----------------------------------------------------------------
4-1. 共有データ保存先（data_root ＝ 現場ごとのdataフォルダ）
  配布時の初期値:
    I:\マイドライブ\KY安全管理\001_芝原改良工事\data
  ※ローカルフォルダ（例 C:\KYデータ）やNASのUNCパス
    （例 \\サーバー名\共有名\フォルダ）も指定可能です。

  data_root 配下の構成:
    records\YYYY-MM\{ID}.json   KY解析の履歴1件ごとのJSON
                                （作成日時・作成者・現場名・作業内容・
                                  主な危険・解析結果Markdown・モデル名等）
    records\YYYY-MM\{ID}.deleted 削除印（履歴を消す場合、JSONは残し印のみ作成）
    images\YYYY\MM\{ID}.jpg 等  アップロードされた写真
    reports\{ID}\               生成したPDF・Excelレポート
    export\                     履歴をZIPで書き出したファイル

  ・NAS/共有ドライブは「データ保管」だけを担当します。
    EXE・secrets.env・APIキー・ログは置きません。
  ・バックアップは現場フォルダ全体（records / images / reports / export
    と削除印）が対象です。recordsだけでは写真・PDFを復元できません。
  ・保存先に接続できない場合、アプリは終了せず、履歴の読込・保存・削除時に
    「共有データへ接続できません」等のメッセージを表示します。
    復旧後に再度操作してください。

4-2. 各PCのローカル保存（PC固有・共有されない）
    %LOCALAPPDATA%\KY安全管理\
      logs\            動作ログ（APIキーは記録しない。1ファイル5MBで循環）
      restart.flag     初期設定完了後の再起動用の一時マーカー

4-3. Google側（Vertex AI）に送信される情報
  ・解析のたびに、写真（Base64）・現場名/作業内容/主な危険の入力文・
    指示文が Vertex AI へ送信されます。
  ・送信データの取り扱い（学習利用の有無・保持）は、利用中の
    Google Cloud契約・プロジェクト設定に従います。機密性の高い写真を
    扱う場合は、社内ルールに沿って利用可否を確認してください。

----------------------------------------------------------------
5. 保存データの種類と注意（個人情報等）
----------------------------------------------------------------
  ・履歴には作成者名・現場名・写真が含まれます。写真に人物や車両番号が
    写り込む場合は、社内の個人情報の取り扱い方針に従ってください。
  ・共有フォルダのアクセス権は、現場の関係者のみに限定してください。

----------------------------------------------------------------
6. 運用チェックリスト（管理者向け）
----------------------------------------------------------------
  [ ] 各PCに secrets.env が配置され、VERTEX_API_KEY が設定済み
  [ ] config.json の data_root が正しい現場フォルダを指している
  [ ] data_root 配下に records / images / reports / export がある
  [ ] secrets.env がNAS・Git・メール等に出ていない
  [ ] 現場フォルダ全体が定期バックアップ対象になっている
  [ ] APIキーの管理者・再発行手順が決まっている
